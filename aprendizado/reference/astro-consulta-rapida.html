Astro

O que você precisa ter à mão enquanto escreve. A explicação inteira está em Astro em Duas Linguagens.

A regra que resume tudo: acima dos três traços roda na sua máquina; abaixo vira HTML. JavaScript no navegador só existe se você escrever um <script> ou uma diretiva client:.

Anatomia de um .astro

---                              ← abre o frontmatter
import Card from '../components/Card.astro';
import dados from '../data/advogados.json';
const { titulo } = Astro.props;   ← props recebidas
---                              ← fecha. NADA acima cruza a rede.

<section>
  <h2>{titulo}</h2>            ← expressão JS no template
  {dados.map(d => <Card {...d} />)}
  <slot />                       ← buraco para o HTML filho
</section>

<style>                          ← CSS com escopo neste componente
  section { display: grid; }
</style>

<script>                         ← ESTE roda no navegador do visitante
  document.querySelector('button')?.addEventListener(...);
</script>

As seis diretivas de cliente

Só funcionam em componentes de framework de UI (React, Svelte, Vue) com a integração instalada. Sem diretiva, o componente vira HTML estático e não envia JS.

DiretivaPrioridadeQuando o JS carregaPara quê
nenhuma—Nunca; não há JSO padrão. O que este projeto usa quase sempre
client:loadAltaImediatamente, na carga da páginaUI visível de cara que precisa responder já
client:idleMédiaApós a carga inicial, no requestIdleCallback. Aceita timeout em msUI de baixa prioridade que não precisa responder de imediato
client:visibleBaixaAo entrar na tela. Aceita rootMarginAbaixo da dobra, ou pesado demais para carregar à toa
client:mediaBaixaQuando a media query passa a valerSó numa faixa de tela — a única que economiza bytes no celular
client:only="react"—Imediatamente, sem HTML do servidorVedado para conteúdo primário neste projeto

A diretiva decide quando, nunca quanto. Os bytes de client:load e client:idle são idênticos. Para caber nos 15 KB do ADR-0002, a decisão que importa é não criar a ilha.

Pares que se confundem

frontmatter × <script>

Mesma linguagem, mundos opostos.

frontmatter roda uma vez, na sua máquina, no build. Nunca é enviado.
<script> roda toda vez, no celular do visitante. Sempre é enviado.

ilha × <script> em .astro

Os dois deixam a página interativa; só um é “ilha”.

Ilha exige framework de UI instalado + diretiva client:.
<script> é JS puro; o Astro o empacota, deduplica e embute se for pequeno. Este projeto provavelmente usa só isto.

renderizar × hidratar

O intervalo entre os dois é o que o visitante sente como “travado”.

Renderizar é desenhar na tela.
Hidratar é ligar o comportamento no que já está desenhado.

src/ × public/

Decisão de bytes disfarçada de decisão de organização.

src/ é transformado, otimizado e empacotado — AVIF, WebP, srcset.
public/ é copiado “as-is, with no processing”. Foto aqui = orçamento estourado em silêncio.

zero JS × JS adiado

O par que resolve a pergunta original.

Zero JS significa que o arquivo não existe. Custo: 0 KB.
Adiado significa que ele existe e chega depois. Custo: o mesmo de sempre.

Imagens

  • <Image /> — transforma dimensão, formato e qualidade; infere as dimensões (evita CLS); aplica loading="lazy" e decoding="async" por padrão.
  • <Picture /> — emite <picture> com AVIF e WebP mais o fallback. É o que gera os 36 arquivos das 6 fotos.
  • Fonte da imagem em src/, sempre, quando for conteúdo.
